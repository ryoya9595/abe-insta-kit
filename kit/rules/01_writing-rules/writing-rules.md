## 基本ルール

### 台本の基本構造

```
冒頭 → 理由/共感 → 本編 → CTA
```

理由/共感は冒頭の興味を本編を見る動機に変換するブロック。中身は投稿パターンによって変わる。問題提示・ハードル下げ・実績証明・ベネフィットなどが入る。対話型ランキングのように冒頭と本編が一体になり、理由/共感が独立しないパターンもある。本編では冒頭で約束した内容を回収し、CTAは価値を出し切ってから入れる。保存誘導とCTAの書き方は、下の「保存誘導」「CTA」セクションを参照。

### 台本の長さ

尺は選んだ型の見本台本（参考投稿がある場合は参考投稿）を基準に決める。完成台本が見本より明らかに長くなった場合は、打ち手を削ってから出す。下の表は上限の目安。

| 尺 | 行数目安 | 文字数目安 |
|---|---:|---:|
| 短尺 | 約20〜25行 | 約300〜500文字 |
| 中尺 | 約30〜40行 | 約500〜800文字 |
| 長尺 | 約50〜90行 | 約800〜1200文字 |

### 1投稿1テーマ

1本の台本で扱うテーマは1つに絞る。視聴後に「何の投稿だったか」を一言で言えない台本は弱い。

NG：「ChatGPTの使い方と副業の始め方とおすすめAIを紹介」
OK：「ChatGPT Gemini Claudeが化ける / 最強プロンプトTOP5」

複数ツールが出ていても、テーマは「プロンプト」で統一されている。

## 冒頭

冒頭3秒が最も重要。ここでリールを見るか見ないかが決まる。

冒頭 = 最初の1〜3行。ここで「続きが気になる」と感じさせる。

以下の要素から2〜3個を冒頭に入れる。具体性はほぼ必須。

### 意外性

市場の常識や共通の価値観に逆張りする。

- 常識破壊：「ChatGPTの時代は終了しました」
- 逆張り：「ChatGPTだけ使ってる人は時代遅れです」

### 危機感

今のまま何もしないと損する、遅れると感じさせる。

- 損失：「使い方わかってない人は損してる」
- 警告：「これやってないならChatGPT使わないで」
- 指摘：「まさかChatGPTにいきなり〇〇してなんて言ってないですよね」

### 有益性

このリールを見たら何が得られるかを先に見せる。

- ベネフィット：「ChatGPTでプロンプトを2回繰り返すと回答精度が爆上がりします」「ChatGPTに旦那の愚痴を聞かせると月5万狙えます」「実はChatGPT LINEと組み合わせると自動で収益作れます」
- 権威性：「インスタ始めて4ヶ月で1000万作った僕が」「海外で大バズリの」

### 具体性

何の話なのかを固有名詞や数字で一瞬で分かるようにする。冒頭が抽象的だと「何の動画か分からない」で離脱される。

- 固有名詞：「**ChatGPT**でよく見るこの4つの記号」「なんと**LINE**で**Manus**が使えるようになりました」「まさか**ChatGPT Gemini Claude**にいきなり〇〇してなんて言ってないですよね」
- 数字：「ChatGPTに旦那の愚痴を聞かせると**月5万**狙えます」「ChatGPTが化ける最強フレーズ**TOP5**」「インスタ始めて**4ヶ月**で**1000万**作りました」

固有名詞はほぼ必須。数字はあるとさらに強くなるが、なくても成立する。

#### 抽象度の基準

同じテーマでも書き方で刺さり方が変わる。以下は「ChatGPTのプロンプト」をテーマにした例。

```
レベル1（ボツ）：「ChatGPTはプロンプトが大事です」
レベル2（弱い）：「ChatGPTでプロンプトを工夫すると回答が良くなります」
レベル3（使える）：「ChatGPTでプロンプトを2回繰り返すと回答精度が爆上がりします」
```

レベル1は誰でも言えるし何も具体的じゃない。レベル2は方向性はあるけど「工夫」「良くなる」が曖昧。レベル3は「2回繰り返す」という操作と「精度が爆上がり」という結果が入っていて、すぐ試したくなる。

冒頭はレベル3で書く。

### 続きが気になる

冒頭で全部を言い切らず「なぜ？」「どうやって？」「いくら？」を残す。

- 好奇心：「ChatGPTの怖すぎる使い方見つけました」
- 未完結：「◯◯を1ヶ月続けた結果 想像と違うことになりました」
- 意外な組み合わせ：「ChatGPTに / 旦那の愚痴を聞かせると / 月5万狙えます」

### 強調ワード

最初の一言で感情を立ち上げる短い言葉。単体では機能しない。意外性や危機感、新情報とセットで使う。

- 「え？やばくない？」
- 「衝撃です」
- 「見てこれ凄すぎませんか？」
- 「革命が起きました」

### よくある組み合わせ

| 組み合わせ | 例 |
|---|---|
| 意外性 × 具体性 | 「ChatGPT実は… / LINEと組み合わせると / 自動で収益作れます」 |
| 危機感 × 具体性 | 「ChatGPTでよく見るこの4つの記号 / 使い方わかってない人は損してる」 |
| 有益性 × 具体性 | 「ChatGPTでプロンプトを2回繰り返すと / 回答精度が爆上がりします」 |
| 強調ワード × 意外性 × 具体性 | 「え？やばくない？ / ついにAIで自分の分身を作って / インスタ発信できる時代が来た」 |

### 伸びない冒頭

- 抽象度が高すぎる：誰にでも当てはまるけど、ターゲットが広すぎて誰にも刺さらない
- 意外性ゼロ：みんなが知ってることをそのまま言ってるだけ
- 普通すぎる：価値がない。見ても何も得られなさそう
- 中身が伝わらない：煽ってるけど何がすごいのか具体的に言ってない
- ハードルが高すぎる：難しい専門用語や馴染みのないツール名から始まって離脱される

#### 伸びなかった実例

**伸びなかった台本の冒頭（6,971回）**
「AIで誰でも簡単にアプリを作る方法を教えます」
→ 「AI」が抽象的で、「アプリを作る」も広すぎて刺さらなかった

### フックの使い方（rules/04_hooks/hooks.md）

冒頭の候補は毎回3系統から出す——①今回の見本（参考投稿）の冒頭 ②data/04_post-samples/のストックのフック（自分の勝ちパターン含む） ③rules/04_hooks/hooks.md のテンプレ集。並べて一番強いものを選び、この「冒頭」セクションの要素でテーマに合わせて微調整する。

- 見本の冒頭＝実績つきの実物。毎回必ず候補に入れる
- テンプレ集＝複数アカウントが使う定番構文。定番はそのまま使ってよい（◯◯を自分のジャンルに置き換える）
- 迷ったら：定番構文＝そのまま寄り／見本固有の言い回し＝型だけ借りて中身を変える

## テーマの性質に合わせて訴求を選ぶ

訴求はテーマで変える。テーマを見ずに型から訴求を決めると、どんなテーマでも同じ冒頭・同じ訴求になって刺さらない。まずテーマの性質を見極め、それに合う訴求を選ぶ。選んだ訴求は冒頭に最も強く出て、本編も同じ訴求で貫く。

以下は代表的なテーマの性質と、効く訴求・冒頭例。これで全部ではない。テーマごとに見極めるのが原則。

**①既に知っている／見たことはあるが使いこなせていない**
存在は認識されている。だから「使えてないと損している」が効く。
- 効く訴求：危機感（損してる／時代遅れ）、有益性（使えると何が変わるか）
- 冒頭例：「ChatGPTでよく見るこの4つの記号 使い方わかってない人は損してる」

**②存在自体を知らない**
知らないものは失えないので「損してる」はピンとこない。発見・好奇心で「何それ？」を作る。
- 効く訴求：意外性・好奇心（見つけました／怖すぎる）、具体性で何の話か見せる
- 冒頭例：「ChatGPTの怖すぎる使い方見つけました」

**③新しいもの・新情報（新商品・新機能・アップデート）**
話題性そのものが武器。「ついに出た」と新しさを前に出し、何ができるかでワクワクさせる。
- 効く訴求：意外性（ついに／〇〇の時代は終了）、強調ワードで驚きを立ち上げる（革命が起きました／衝撃です）、有益性（何ができるか）
- 冒頭例：「ChatGPTの時代は終了しました ついに全てのAIを越えた神AIが登場」

**④結果・再現性が主役（数字・実例で見せる）**
「自分にもできそう」が壁。結果（収益・変化・達成）を数字と実例で具体化し、ハードルを下げてワクワクさせる。
- 効く訴求：有益性（数字つきベネフィット）、ハードル下げ（属性・費用・工程）
- 冒頭例：「ChatGPTに旦那の愚痴を聞かせると月5万狙えます」

## 台本全体のルール

### 一次情報

客観的な事実だけではダメ。Googleで検索したらすぐ分かる情報、AIに聞けばすぐ出てくる情報だけでは価値がない。その人にしか届けられない情報、経験、体験談を入れる。

一次情報は以下の種類から入れる。

**実際に試した・使ってみた結果**
ツールの紹介や機能説明だけで終わらせず、実際に使った結果を入れることで「自分も試したらこうなるかも」とイメージさせる。
「実際に僕自身 / インスタの台本作成 / noteの記事作成 / YouTubeのサムネ作成 / に使ってみたら / 作業効率もクオリティも10倍変わりました」

**視聴者の事例**
「稼げます」と言うだけでは自分ごとにならない。誰がどれくらいの成果を出したかを入れることで「この人にもできたなら自分にもできそう」と思わせる。
「子育て中の視聴者さんが / たった1ヶ月で収益化 / さらにチャンネルを売却して一気に25万作りました」
「主婦の視聴者さんが / 1ヶ月で5万 / 2ヶ月で15万作りました」

**自分の実績**
「この副業がアツい」と言うだけでは説得力がない。特にノウハウ系では、自分がどれだけの成果を出してきたかを見せることで「この人が言うなら信頼できる」となる。
「インスタ始めて4ヶ月で1000万作った僕が」
「SNS総フォロワー34万人の僕が」

**失敗談・やめた方がいいこと**
発信してきた中で「これはダメだった」「これはもう通用しない」と分かったこと。経験から得た注意喚起で、それ自体が一次情報になる。
「前は再生が回って稼ぎやすかったんだけど / 今はどのSNSも規制が強くなってて / BANされるリスクが高くなったから / オススメしません」
「ただしなんとなくAIで作っただけの投稿は / もう伸びにくくなってるから / 自分の体験や独自性を入れるのが超重要」

チェック：「この内容、ChatGPTに聞いて出てくる答えと同じか？」同じならボツ。

### 数字

数字がないと視聴者はイメージできない。「稼げます」ではどれくらいの話か分からないし、「短時間でできます」ではどれくらい短いのか伝わらない。「月5万狙えます」「3分で終わります」まで書いて初めて具体的になる。

数字は大きく分けると、**事実として扱う数字**と**見せ方として使う数字**がある。前者は根拠が必要で、後者は構成の整合性が必要。役割が違うから分けて考える。

**事実として扱う数字**：収益・実績・フォロワー数・期間など、視聴者が「本当にそうなんだ」と受け取る数字。証拠や確認済みの事実がないなら使わない。

- 月5万、月100万、1000万（収益実績）
- 24.8万人（フォロワー数）
- 4ヶ月で、1ヶ月で、2週間で（達成期間）

端数でリアル感を出す時もあるし、「月5万」みたいに丸める時もある。見せたいリアル感に合わせる。

**見せ方として使う数字**：ランキング・手順・項目数・割合など、内容を整理して見やすくする数字。根拠は不要だが、中身とズレた数字は使わない。

- TOP5、TOP10（ランキング）
- 3STEP、5STEP（手順分割）
- 4つの記号（テーマの数字化）
- 9割（割合で印象づけ）

### 行動のハードルを下げる

視聴者が「自分には無理だ」「難しそう」と感じた瞬間に離脱される。最後まで見てもらうには「これなら自分にもできそう」と思わせる必要がある。

ハードルを下げるのもイメージの話で、「簡単です」だけでは伝わらない。「コピペするだけ」「3STEPで」「無料で」まで見せて初めて「できそう」とイメージできる。

**属性**：「初心者の人でも」「主婦でも」「漫画が書けない人でも」のように、視聴者と近い属性を出して「自分と同じような人ができてる」と思わせる。

**費用**：「無料で使える」「完全ノーリスク」「在庫いらずで」のように、お金がかからないことを見せて金銭的な不安を消す。

**操作**：「コピペするだけ」「送るだけ」「一言入れるだけ」のように、やることを簡単な動作1つに見せる。

**工程**：「3STEPで」「5分で」「やり方は超簡単で」のように、手順が少ない・時間がかからないことを数字で見せる。

**条件**：「顔出しなしで」「プログラミング知識ゼロでも」「SNS一切使わずに」のように、視聴者が「自分にはないから無理」と思いがちな前提を外す。

「初心者でも簡単にできるから今すぐ保存して試してみて」のように、ハードル下げ+保存誘導をセットで使うことも多い。

### 感情設計

リールは一番リーチされるフォーマットで、視聴者との出会いの場。自ら探して見に来るわけではなく、おすすめで流れてくる。その視聴者の感情を冒頭から最後まで設計する。

あなたのリールに出会う視聴者がどんな状態か（何に悩み、何を知らないか）は data/01_profile/profile.md のターゲット欄で定義する。その人の状態から感情設計を始める。

台本全体を通じて、感情を4段階で動かす。

**「気になる」を作る（冒頭）**
意外性・危機感・有益性で「え、何それ？」「知らないとまずい？」を作る。ここで止められないと本編は見てもらえない。

**「見る価値がある」と確信させる（理由/共感）**
冒頭で生まれた興味を、本編を見る動機に変える。問題を具体化する、ハードルを下げる、実績を見せる、ベネフィットを具体化するなど、パターンによって手段が変わる。

**「できそう」と思わせる（本編）**
手順・フレーズ・ツールの使い方を具体的に見せて「自分にもできるかも」に変える。事実だけ並べると感情が動かないから、一次情報やリアルな感想を入れる。

**「試したい」「欲しい」に変える（CTA）**
価値を出し切った後で、具体的な配布物を提示する。保存誘導は本編前に、CTAは最後に。

感情の流れを崩さない。「できそう」の前に「難しそう」が来ると離脱される。

投稿パターンごとの感情設計は `rules/03_post-patterns/index.md` を参照する。

### 専門用語は噛み砕く

市場には初心者が多い。専門用語が出てくると「自分には難しそう」と感じて離脱される。専門用語が必要な場合は、直後に一文で噛み砕く。

例：
「これLINE Botという / AIが自動返信するプログラムで」
「noteっていうのは / 自分の書いた記事を / 有料販売できるサービスなんですが」
「楽天ROOMっていうのは / 楽天アカウントさえあれば / 誰でも簡単に始められるアフィリエイトサービスで」

例文の台本で実際に噛み砕いている言葉：LINE Bot、note、GAS、楽天ROOM

LINE BotやGASのように技術的な話が出るテーマでは、離脱される前に安心材料を置く。
例：「ちょっと難しい言葉を使うけど / 分かりやすい手順書も用意したから最後まで見て」

噛み砕けない言葉は使わない。

### リアル感

台本が「作られた感」や「広告っぽさ」を出すと視聴者は離脱する。「実際に使ってみた人が本音で話してる」感覚が大事。

**自分の状況を入れる**
「僕がプールで遊んでる間に / Chromeを開いてXで検索して情報をまとめてくれます」
「実際に僕自身 / インスタの台本作成 / noteの記事作成に使ってみたら」
自分が実際に使ってる場面を入れると、紹介ではなく体験談になる。

**率直な感想を入れる**
「正直怖くなるレベルで言ってくるんですが」
「完成度おかしいです」
「正直使ってないと損するレベルです」
きれいにまとめず、本音で感じたことをそのまま出す。

**視聴者の反応を先回りする**
「冗談だと思うかもしれないけど」
「なんだ自己分析かって思った人 / これ実は恐ろしいくらい丸裸にされます」
視聴者が「本当に？」「大したことないでしょ」と思いそうな場所で、先に反応を拾う。

**完璧に見せようとしない**
「ちょっと難しい言葉を使うけど / 分かりやすい手順書も用意したから最後まで見て」
「もう何度も言うけど / 今すぐインスタ始めてください」
弱みや繰り返しも隠さない方が信頼される。

**文体のムラを許容する**
全部の台本が同じトーン・同じテンションだとAI感が出る。テーマに合わせてテンションを変える。

- 注意喚起がテーマの台本：警告のトーン
- 新発見がテーマの台本：驚き・ワクワクのトーン
- ネタ寄りのテーマの台本：カジュアル・面白系のトーン
- ノウハウ紹介の台本：教える・リスト紹介のトーン

（例文の発信者の実台本も、テーマごとにトーンが全部違う）

同じ温度感で書き続けると不自然になる。テーマごとに変える。

### 強いワード

弱い表現より強い表現を選ぶ。強いワードを使うと視聴者の感情が動く。「良くなります」では何も感じないが「爆上がりします」なら印象に残る。印象に残らない台本は保存もコメントもされない。

- 「非常に便利」→「エグいくらい便利」
- 「とても高性能」→「正直別次元」
- 「大きな効果」→「劇的に変わる」

例文の台本で使われている強いワード：
「爆上がり」「別次元」「最強」「神」「エグい」「ヤバい」「激アツ」「怖すぎる」「凄すぎる」「衝撃」「革命」「ぶっちぎる」

「マジで」「ヤバい」「正直」「激アツ」は、テーマに合えばそのまま使う。

### 保存誘導

保存誘導は台本の途中で「この投稿を保存しておきたい」と思わせること。CTAとは別。台本の最後はCTAの場所なので、保存誘導を最後に置かない。

入れるかどうかは固定ルールにしない。参考投稿や選んだ型の実例台本の流れに従い、実例に無ければ無理に入れない。

入れる場合は、独立した呼びかけの行として挟まず、直前の文に一言で続ける。文言は固定にせず、テーマと流れに合わせる（例の丸写しをしない）。冒頭の約束（「やり方をシェアします」等）と保存誘導を、離れた場所に分けて二度呼びかけない。
- 「やり方をシェアします 忘れないうちに保存して試してみて」
- 「初心者でも簡単にできるから今すぐ保存して試してみて」

例文の台本での使い方：
「今すぐ保存して試してみて」
「忘れないうちに保存して試してみて」
「保存して今すぐやってみて」

### CTA

CTAの型やコメントのお題は `rules/03_post-patterns/index.md`（投稿パターン索引）を参照する。ここでは書き方の原則だけ扱う。

- CTAは台本の最後に置く。価値を出し切る前にCTAを入れない
- 配布物は具体的に名前を出す：「プロンプト」「手順書」「解説動画」「GPTs」
- 「欲しい人は」「まとめたので」で、コメントする理由を明確にする
- コメントのお題は回答ハードルが低い日常系にする

例文の台本での使い方：
「今回使ったプロンプトと / 手順書 / 解説動画が欲しい人は / この投稿にいいねして / 「好きな食べ物」をコメントしてください」
「欲しい人はこの投稿をいいねして / 「好きな動物」をコメントしてください / DMにこっそり送ります」

## テンポ感

リールはテンポ感が命。テンポが悪いと視聴者が離脱する。台本は読み上げが前提で、話す言葉として自然に聞こえるように書く。声に出したときにリズムよく流れるか、引っかからないかが基準。

**語尾に変化をつける**
語尾が同じだと単調で飽きやすく、離脱される。同じ語尾を3つ以上続けない。

語尾のパターン例：
- 断言：「〜です」「〜ます」
- 体言止め：「それがAI」「動画が完成」
- 口語命令：「〜してみて」「〜してください」
- 否定：「〜しません」「〜ない」
- 問いかけ：「〜ですよね」「〜ませんか」
- 口語理由：「〜から」「〜ので」
- 口語逆接：「〜けど」「〜んですが」

これが全てではない。大事なのは同じ語尾が続かないこと。

本編の例（プロンプト紹介の台本）：
「ChatGPTって基本褒めてくるから」→ 口語理由
「あえて批判的になってもらうことで」→ 接続
「本当に忖度無しで答えてくれます」→ 断言
「正直怖くなるレベルで言ってくるんですが」→ 口語逆接
「自分では気づけない穴が全部見つかります」→ 断言

本編の例（ランキングの台本）：
「ChatGPTで手相を分析して」→ 連用形
「ココナラで鑑定結果を販売する副業」→ 体言止め
「主婦の視聴者さんが」→ 主語提示
「1ヶ月で5万」→ 体言止め
「2ヶ月で15万作りました」→ 断言

**口語を入れる**
「マジで」「正直」「って」「しかも」「なんなら」「超」のような口語を入れると、読み上げたときに「喋ってる」感が出てテンポが自然になる。書き言葉だけで構成すると読み上げたときにテンポが重くなる。

**接続詞を意識する**
接続詞が重要なのは、文章を繋げてテンポを維持するため。「。」で終わらせず接続詞で次の文に繋げると、聞いてる方も続きが気になるし、テンポが途切れない。接続詞はテンポの道具である前に、意味が合っていることが前提（順接・逆接・補足を取り違えない）。

「しかも」「でも」「だから」「なんなら」「ちなみに」「実は」「正直」「ということで」を中心に使う。「そして」「また」「さらに」は堅くなるから基本使わない。接続詞が被らないようにする。

**削る意識**
冗長な表現は削る。同じ意味が伝わるなら短い方がいい。冒頭で言ったことを本編の前でまた繰り返すと「もう聞いた」と思われて離脱される。新しい情報を足すか、コンパクトにまとめる。

**2〜3行のかたまりで伝える**
1つの情報を2〜3行で伝えて、次のかたまりに移る。例文の台本でも2〜3行で意味の区切りが来ている。厳密なルールではなく目安。

「ChatGPTで / 手相を分析して / ココナラで鑑定結果を販売する副業」
→ 3行で何をする副業か伝わる

「主婦の視聴者さんが / 1ヶ月で5万 / 2ヶ月で15万作りました」
→ 3行で実績が伝わる

これがあると、聞き手が情報を区切りごとに消化できる。長い説明が区切りなく続くと頭に入らない。

**宣言文で間を作る**
話題が変わるポイントに短い宣言文を置くと、聞き手の注意がリセットされて次の話題に集中できる。毎回使うものではなく、ここぞという場面で使う。

「これが一番ヤバい」→ ランキング1位の前
「マジですごすぎる」→ 実演結果の前

宣言文は感情の爆発であって、進行の案内ではない。「で 結果ですが」「先に言うと」は宣言文ではなく区切りの案内＝NG（「AI感を消す」の「5. 話の区切りを案内してしまう」を参照）。

**てにをはに違和感がないか**
助詞の使い方が不自然だと、読み上げたときに引っかかる。声に出して読んで違和感があるなら直す。

**「て」の連鎖に注意**
「〜して」「〜して」と連用形が続くと息苦しくなる。例文の台本でも「て」の連続は2つまでに収まっている。

「GASを開いて / このプロンプトを使って / Botプログラムを作ります」
→ 「開いて」「使って」の後に「作ります」で言い切って区切っている

句読点は使わない（正式ルールと例外は rules/02_ng-rules/ng-rules.md「②デフォルトスタイル」に一本化）。短い行で区切る。

同じ構文が3回続いたら書き直す。

## AI感を消す

このセクションは「リアル感」「強いワード」「テンポ感」とは別の役割を持つ。リアル感は「何を入れるか」、強いワードは「語彙の強弱」、テンポ感は「読み上げリズム」の話。AI感を消すは「AIが構造的に生み出す不自然さを理解し、潰す」ための原則・指標・チェック方法を扱う。

### AIっぽい文章の5つの特徴

#### 1. 均一すぎる

文の長さ・構造・語彙レベルが一定になる。同じテンションが続き、同じ構文パターンが並び、同じ粒度で情報が整列する。

**AIが書くとこうなりがち（ランキング台本）：**
> スタッフ）ChatGPT
> あべさん）これは2位です。文章生成に優れたAIです。特徴は汎用性が高いことで、さまざまな用途に活用できます。
>
> スタッフ）Vrew
> あべさん）これは3位です。動画編集に優れたAIです。特徴は字幕生成が簡単なことで、初心者でも使いこなせます。
>
> スタッフ）Manus
> あべさん）これは1位です。リサーチに優れたAIです。特徴は自動分析ができることで、作業時間を大幅に短縮できます。

全項目が同じ型。テンションも粒度も揃っている。

**人間が書いた実台本はこう（同じテーマのランキング台本）：**
> スタッフ）ChatGPT
> あべさん）うーん、論外 じゃなくて2位！
> 最近ChatGPTは論外！って言う人多いけど
> それ全部間違ってます
>
> スタッフ）Vrew
> あべさん）うーん5位！
> 革命的な動画編集AI
>
> スタッフ）Manus
> あべさん）1位！
> AIエージェントの王様

項目ごとに文の長さも構造もバラバラ。ChatGPTのところで急に長く語り、Vrewは短く切り上げる。

#### 2. 客観的すぎる

AIは公平で客観的な視点を取る。どちらかに肩入れせず、両方の良い点を並べる。人間は断定する。

**AIが書くとこうなりがち：**
> ChatGPTにも強みがありますが、Geminiも注目されています。どちらもそれぞれの用途に適しているので、目的に応じて使い分けるのがおすすめです。

**人間が書いた実台本はこう：**
> ChatGPTの時代は終了しました
> ついに全てのAIを越えた神AIが登場しました
> ——Gemini3リリース

> ChatGPTだけ使ってる人は時代遅れです
> ——シーン別おすすめAI

片方を断言で切り捨てている。リール台本では「目的に応じて使い分けましょう」は機能しない。

#### 3. 完璧すぎる

文法的に正しく、論理的に整合性が取れた文章を書く。隙がない文章は読み上げると嘘くさくなる。

**AIが書くとこうなりがち：**
> 新しいGPT-Image2は、従来の画像生成AIと比較して日本語対応が大幅に改善され、文字の描画精度も向上しました。ウォーターマークが表示されない点も大きなメリットです。

文法的に完璧。情報も整理されている。だが何も感じない。

**人間が書いた実台本はこう（新しい画像生成AIを紹介した台本）：**
> 完成度おかしいです

（プロンプト紹介の台本）：
> 正直怖くなるレベルで言ってくるんですが

「完成度おかしい」は日本語として崩れている。「怖くなるレベルで言ってくる」は文法的に雑。この崩れが体温になる。

#### 4. 感情がフィルタリングされている

AIは感情を丁寧にまとめる。「便利です」「効果的です」「おすすめです」。報告書のような温度感になり、体温が抜ける。

**AIが書くとこうなりがち：**
> 非常に便利です
> 大きな効果があります
> この機能を活用すると、作業効率が向上し、満足度の高い結果が得られるでしょう。

**人間が書いた実台本はこう（新機能を紹介した台本）：**
> LINEで完結するのがエグいくらい便利だから

（AIツール紹介の台本）：
> 僕がプールで遊んでる間に
> Chromeを開いてXで検索して情報をまとめてくれます

「エグいくらい便利」は「非常に便利」の100倍体温がある。「プールで遊んでる間に」は論理的に不要な情報だが、これがあるから人間の発話になる。

#### 5. 話の区切りを案内してしまう

AIは型の手順に従って書くとき、「今から何を話すか」を先に案内しがち。書き言葉なら道案内として機能するが、リールで読み上げると司会になり、中身のない行で離脱される。

**AIが書くとこうなりがち：**
> で 検証の結果ですが
> 売れたのは著作権切れのパズルだけでした

**案内を削って中身から入るとこう（同じ場面）：**
> 実際に売れたのは
> 著作権切れのパズルだけでした

案内の行（「先に言うと」「で 結果ですが」「まず結論から言うと」「ここからは〇〇」）は削って、次の文からそのまま始める。例文の台本でブロックの間に挟まるのは「作り方は超簡単です」のような中身のある橋（ハードル下げ）であって、中身のない案内ではない。
冒頭の約束（「やり方をシェアします」「3STEPで教えちゃいます」）、感情の宣言文（「これが一番ヤバい」）、実際にやった行動の順序（「まずは〜」「そしたら〜」）はOK。禁止は区切りの案内だけ。

### 人間らしさの5つの指標

**ムラがある**
文の長さもテンションも揃っていない。「え？やばくない？」という突発的な短文と、「AIが自分の表情や体の動きを完全にコピーして顔・髪・服もそして声も変えてくれるんです」のような畳みかける長文が混在している。

**偏っている**
客観的な情報提供ではなく「この人はこう思ってる」という主観が出ている。「ChatGPTの時代は終了しました」「ChatGPTだけ使ってる人は時代遅れです」のような断定。偏っていい。

**隙がある**
「完成度おかしいです」「正直怖くなるレベルで言ってくるんですが」のような、文法を気にせず感想をそのまま出した表現。整いすぎていない。

**感情がフィルタリングされていない**
例文の発信者の実台本を再生数で並べると、高再生の台本は全て語り手の感情がフィルタリングされずに出ている。低再生の台本は機能説明に寄って感情が薄い。

**語り手の存在感**
読んでいて「この人がここにいる」と感じるかどうか。思考の途中経過や判断の揺れが見えると存在感が出る。

- 「うーん、論外 じゃなくて2位！」→ 思考の揺れが見える
- 「冗談だと思うかもしれないけど」→ 自分でも信じがたいと認めた上で話す
- 「なんだ自己分析かって思った人 / これ実は恐ろしいくらい丸裸にされます」→ 視聴者の反応を拾ってからひっくり返す
- 「もう何度も言うけど」→ 繰り返しを自覚している。AIは同じことを二度言わない
- 「僕がプールで遊んでる間に」→ 語り手の状況が見える

否定→肯定の回り込み、まとめ構文、両論併記、回りくどい前置き、Before/After対比はAIが出しやすいパターン。台本に残っていたら書き直す。話の区切りの案内（内容予告）は上の「5. 話の区切りを案内してしまう」を参照。感情表現の語彙置き換えは「強いワード」セクションを参照。

### AI感チェック（完成後に確認）

- **均一性チェック**：文の長さ・構造・テンションが同じパターンで続いていないか
- **主観チェック**：「〇〇もありますが」「どちらも」のような両論併記が残っていないか。断定しているか
- **完璧さチェック**：文法的に完璧すぎる文がないか。読み上げたとき「教科書を読んでいる感じ」がしないか
- **感情フィルタリングチェック**：「便利です」「効果的です」「おすすめです」のような温度のない表現が残っていないか
- **案内チェック**：話の区切りを案内する行（「先に言うと」「で 結果ですが」）が残っていないか

## 参考投稿の使い方

参考投稿がある場合の転用ルール。型（核）は借り、テーマ固有の中身（周辺）は変える。

### 1. 複数あれば、共通する型を抜く

2〜3本あると、見比べて共通する型（＝核）と本ごとに違う中身（＝周辺）を分けられる。
例（冒頭）：「この収納 知らない人は損してます」「9割が知らない収納の裏ワザ」「収納で損してる人 まだいますか」→ 共通＝知らないと損という危機感で入る＝核。
共通する型（構造）だけでなく、全部の参考が共通して言っている魅力・主張も列挙する。複数の発信者が揃って言っていることは、その題材の売りである可能性が高い。列挙した魅力のうちどれを冒頭〜本編の前で約束するかは、設計メモに書いてあなたの確認を取る。
参考投稿も他人の投稿なので、素材と同じ「体験談は発信者のもの」の原則が当てはまる。参考の中にある発信者自身の体験・実績・感想・体感の数字はその発信者のもの。型は借りても、これらを自分のこととして台本に持ち込まない。中身を使いたい場合は、体験の形を外して「〜してくれます」の性質の説明に言い換える（複数の参考や公式で裏が取れるものだけ。1人だけの体感の数字は使わない）。
1本だけの時は丸パクリしやすい。型だけ借りて、中身（固有名詞・具体例・お題）は全部変える。

### 2. ブロックに分けて核/周辺を見分ける

冒頭／理由・共感／本編／CTAに分ける。台本によりブロックは減る（早見表型はいきなり本編＋CTA、対話型ランキングは冒頭と本編が一体）。無いブロックは作らない。

全ブロックを飛ばさず分析する。特に冒頭は「どの訴求型か（発見・好奇心／危機感／意外性 など）」まで見極め、自分の冒頭もその型に合わせる（「テーマの性質に合わせて訴求を選ぶ」と連動）。参考が複数あれば、冒頭の訴求型の共通点を見る。

### 3. 核は借り、周辺は「機能」で変換する

核（型）はそのまま借りる。周辺（中身）は、その表現が果たしている機能（フック・ハードル下げ・実績・CTA など）を見抜き、同じ機能をあなた用の別の言葉・自分の道具・自分の数字で果たす。

### 4. 必ず捨てる

- 参考の口調 → あなたの口調（profile）に直す
- 自分にない実績 → 使わない（架空の実績は作らない）

見本が手元に無い場合は台本を作らない。まず競合の伸びてる台本を1本取り込むところから始める（SKILL.mdの絶対ルール4）。

### 通し例（架空・節約ジャンル／1例）

このケースは作るテーマが参考とほぼ同じ（固定費の見直し術）。だから型も中身も大きく変えず、借りられる所は借りて、口調・お題・具体性だけ自分のものにした。テーマが参考と離れている時ほど、中身を大きく変える。

- 冒頭｜型＝知らないと損の危機感で入る｜完成「まだ◯◯に月5000円払ってる人 損してます」｜借りた型に自分のジャンルの固有名詞を入れただけ
- 理由・共感｜型＝ハードル下げ（手続きは◯分）｜完成「見直しはスマホで10分」｜参考の構造をそのまま、自分で確認した事実に差し替え
- 本編｜型＝手順を番号で並べる｜完成「STEP1〜3で見直しの手順」｜流れは同じ。中身は自分のknowledgeにある事実だけ
- CTA｜型＝まとめ配布をコメント誘導｜完成「見直しリストが欲しい人は『好きな飲み物』をコメント」｜お題を自分の定番に

捨てた：参考の口調→自分の口調に。参考の実績数字→使わない（自分の事実だけ）。

## 完成前チェック

1. 冒頭で何の話か分かり、見る理由があるか
2. 冒頭の具体性がレベル3以上か（固有名詞や数字が入っているか）
3. 1投稿1テーマになっているか
4. 一次情報が入っているか（ChatGPTに聞いて出てくる内容だけになっていないか）
5. ハードルを下げているか
6. 感情の流れが崩れていないか（気になる→見る価値がある→できそう→試したい）
7. 専門用語を噛み砕いているか
8. テンポ感（語尾が同じパターンで続いていないか、口語が入っているか）
9. AI感が残っていないか（均一・客観的・完璧・感情フィルタリングの4つ）
10. 文字数が尺に合っているか
11. 話の区切りを案内する行（「先に言うと」「で 結果ですが」）が残っていないか。今回の見本（参考投稿・選んだ実例）と読み比べて、司会・ブログに聞こえる行がないか、尺と流れが見本から大きく外れていないか（ng-rules全体の照合はSKILL STEP5で行う）
