# 新ツール・新情報型

**最終更新日**: 2026-07-07

**この型は何か**: 新しいツール・機能・サービス・ルール変更の話題性で引く型（ジャンルを問わない。例: 新商品・新機能・制度の変更）。何を売りにするかで組み立てが変わるため、新ツール・新機能登場型（何ができるかを売りにする）と仕様変更・ルール変更型（何が変わって・どう対応するかを売りにする）の2つに分ける。既存の機能に追加されたアップデートなどでどちらか迷う場合は、売りが「何ができるか」なら登場型に、「変化への対応」なら変更型に寄せる。

**成立条件（この型を書くのに必要な事実の在庫）**: knowledgeに実在する新しいツール・機能・アップデートの情報があり、何ができるか、または何が変わるかを具体的に説明できること。

## 組み立ての要点

### 新ツール・新機能登場型
- ブロックは冒頭→できること・視聴継続理由→本編→CTA。各ブロックの打ち手は全部入れず、テーマに合うものを1〜2個選ぶ
- 冒頭は「何ができるか」を売る。入り方は主に3つ。強調ワード＋新情報で止める（基本形。危機感だけでは何ができるか伝わらないため有益性を必ず入れる）、「もう使いましたか」のような問いかけで当事者意識を作る、速報トーンで止めてからすぐ「何ができるか」につなぐ
- できること・視聴継続理由は、性能の列挙だけで終えず、視聴者が自分でも使えると想像できる活用シーンとハードル下げをセットで入れる。専門用語は身近な例で噛み砕く。進化幅は「今までは〇〇→今は〇〇」の対比で見せると伝わりやすい
- 従来かかっていたコスト・時間を先に出してギャップで惹く見せ方もある。新機能を複数まとめて紹介する時は3〜5個に絞る
- 本編は操作手順を短く見せる。実演して結果を見せて証明する。メリットだけでなく注意点・弱点も添えると宣伝臭が消えて信頼が上がる
- CTAは詳しい使い方を配布物に誘導する。「今やる人がまだ少ない」と背中を押す一言を添えてもよい

### 仕様変更・ルール変更型
- ブロックは冒頭→何が変わった→対応→CTA。「変化への対応」を売りにする。各ブロックの打ち手はテーマに合うものを1〜2個選ぶ
- 冒頭は変化を断定・速報で止める（「〇〇に仕様変更があった」「緊急で伝える」等）
- 「何が変わった」は旧→新のビフォーアフター対比で見せ、その帰結（誰が損するか・何が効かなくなるか）まで言い切る
- 対応は1テーマに絞る。複数の方向をあれこれ並べない。必要ならそのテーマを2〜3ステップに分けて見せる。テーマに合えば「〜はやめて、逆効果」とやめるべき行動を1つ添えてもよい
- CTAは保存で締めるのと相性がいい（変化への対応は後で見返す情報のため）。標語的なメッセージやコメント誘導で締める形もある
