# 投稿パターン索引

**最終更新日**: 2026-07-07

このファイルは投稿パターン（＝台本の見せ方）の一覧。役割は2つ。

1. **見本の型を特定する**: 台本作成時、今回の見本（参考投稿・保存した実例）がどの型かをこの表で特定し、該当する型ファイルを開く
2. **成立条件を照合する**: その型を「あなたの事実」で書けるかを確認する（捏造防止の線）

型はテーマから機械的に決まるものではなく「見せ方の選択」。同じテーマでも複数の型で作れる（例: 同じ商品でも「使い方の手順を見せる」ならハウツー型、「実際に使った結果を見せる」なら検証・実例型）。**最終決定はあなた（ユーザー）**。

各型ファイルにあるのは「組み立ての要点」（型のノウハウ）。見本の実物（あなたが集めた競合の台本と、あなた自身の勝ちパターン）は **data/04_post-samples/** に溜まっていく——そこがこのキットの見本棚。

## パターン概要

| パターン名（ファイル） | 主役に見せるもの | 成立条件（必要な事実の在庫） | 使う場面・サブタイプ |
|---|---|---|---|
| ランキング型（ranking.md） | 複数候補の順位と評価 | 順位づけできる複数の対象 | 複数の物・方法・道具を比べたい時 |
| 技・方法紹介型（single-prompt.md） | 1つの技・方法の威力 | 実在する技・方法・手順 | 1つのテクニックを見せたい時。単発／並列 |
| ハウツー型（how-to.md） | 真似できる手順 | 実在する再現可能な手順 | 視聴者が同じ手順で再現できるテーマ |
| 新ツール・新情報型（new-tool.md） | 新しさ・話題性 | 実在の新商品・新機能・変更 | 新リリース・変更の話題性で引っ張る時。登場型／変更型 |
| 早見表型（list.md） | 一覧の網羅性（解説なしで並べる） | 並べられる複数の対象 | 用途別おすすめを一覧で見せたい時 |
| Q&A型（qa.md） | 疑問への一点回答 | 視聴者から実際に出る疑問 | 視聴者の疑問に1点で答えたい時 |
| 対話型（dialogue.md） | 相手の証言・本音 | **実在の相手との実際の会話** | 実績者・関係者との会話で一次情報を見せる時 |
| A/B添削型（ab-review.md） | 2つの差の種明かし | **実在の比較対象が2つ** | 「同じなのに◯倍」を解剖する時 |
| 本音・持論型（honne-shucho.md） | 本人の主張・スタンス | 本人が本当にそう思っていること | 情報でなく人柄・本音で共感やコメントを狙う時 |
| 検証・実例型（case-study.md） | 実際に試した結果と気づき | **本人が実際にやった事実** | やってみた過程・結果を見せる時。仮説検証／結果公開 |

**成立条件は捏造防止の線。満たさない型では書かない。** 実際にやっていない検証は書けない。実在の会話が無いのに対話型は書けない。比較対象が無いのにA/B添削型は書けない。

### 成立条件を満たさないときの逃がし先

見本がその型でも、あなたの事実の在庫が足りない場合は、作れずに終わるのではなく次のどちらかを設計メモで提案する:

- **(a) 型を変換する**: 見本から構成・尺・テンポだけ借りて、一人称の体験主張と実績数字を落とした型に変える（例: 「私が試した結果」→事実の紹介＋「試してみて」の形に。数字を出せないなら数字なしで成立する見せ方に）
- **(b) 別の見本を使う**: 成立条件を満たせる型の見本に切り替える（無ければ取り込みを案内）

## ここから下は、型を選んだ後に使う付録

## パターン別の感情設計

台本全体の感情設計（気になる→見る価値がある→できそう→試したい）の原則は `rules/01_writing-rules/writing-rules.md` を参照。ここではパターンごとの感情の流れを示す。

- **ランキング型**: 気になる（冒頭）→ 見る価値がある（問題提起）→ できそう（本編）→ 試したい（CTA）。対話形式のランキングは冒頭と本編が一体になる
- **技・方法紹介型**: 気になる → 見る価値がある → できそう → 試したい
- **ハウツー型**: 気になる → 見る価値がある（ハードル下げ）→ できそう（本編）→ 試したい
- **新ツール・新情報型**: 気になる → 見る価値がある（できること）→ できそう → 試したい
- **早見表型**: 冒頭は任意。テンポよく列挙（本編）→ 試したい。解説せず網羅性で見せる
- **Q&A型**: 気になる（深い疑問）→ え、そうなの?（通説を裏切る）→ 納得（本質1点で答える）→ 試したい（配布）
- **対話型**: 会話で引き込む → 信頼（証言・一次情報・本音）→ 自分ごと → フォロー／CTA
- **A/B添削型**: 気になる（数字ギャップ）→ 見る価値（紐解く宣言）→ なるほど（解剖→種明かし）→ 試したい
- **本音・持論型**: 気になる（本音/逆張り）→ 共感 or 賛否 → ファン化・コメント。配布CTAは必須でなく「呼びかけ／フォロー」で締めることが多い
- **検証・実例型**: 気になる（本当に〜なのか）→ 見たい（結果への期待）→ 納得（結果・実数を見せきる）→ 試したい。盛り・架空数字はNG

## CTA設計ルール

CTAの書き方の原則は `rules/01_writing-rules/writing-rules.md` を参照。ここではCTAの型とコメントお題の具体例を扱う。

- CTAは最後に置く
- 基本形は「いいね + コメント」
- コメントのお題は、回答ハードルが低い日常系にする
- 特典内容は具体化する（「まとめ」「手順書」「リスト」など受け取れるものの名前を出す）
- 「欲しい人は」「まとめたので」「DMにこっそり送ります」で、保存とコメントの理由を明確にする
- 配布物を複数並べると行動理由が強くなる
- 本音・持論型は配布物なしで「共感した人はコメント／フォロー」で締めることもある
