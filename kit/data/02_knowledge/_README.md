# data/02_knowledge/（あなたの知識）

**最終更新日**: 2026-07-07

**あなたの知識を貯める場所。** 学んだこと・調べたこと・検証したこと——YouTubeの文字起こし・公式情報・信頼できる記事・自分の検証メモ。台本の中身（数字・手順・情報）はここ＋profileの実体験からしか使われない＝**あなたの知識に無いことは、AIが勝手に語らない**。

**保存はAIがやる**（「これ素材に入れて」と貼るだけ）。ソースは問わないが、元素材の種類でルールは変えない。

## 置き場・ファイル名

- `data/02_knowledge/<テーマ名>_<日付>.md`（例: `rakuten-room_20260516.md`）
- 1素材 = 1ファイル。日付は元素材の公開日（無ければ取得日）
- 完全に同じテーマ以外は無理に1ファイルにまとめない

## 作り方（AIが守る保存ルール）

- **要約・短縮しない。詳しく残す**（言い回し・たとえ・体験談・数値は原文のまま）
- **原文にない情報を足さない**（推測の注記を勝手に付けない。不確実なものは原文の表記のまま）
- 見出しは元の順番でなく、内容・トピックごとに立てる
- 専門用語・固有名詞・数値・金額・期間・手順は省略しない
- 残すのは、その主題そのものの情報と、主題の理解に必要な背景知識
- 具体的な数字・手順・体験談を厚めに（一般論・教科書的な内容より優先）
- 本筋と関係ないノイズは省く（宣伝・告知・フォロー誘導・雑談・定型の前置き）
- 元素材に視聴者の反応（コメント等）があれば、末尾近くに残す（原文のまま）
- **末尾に必ず「## 参照元」**: 発信者を明記する（**自分の体験か、第三者の情報か**。第三者の体験談・実績は、台本で自分のこととして語れない——この区別が捏造防止の要）

## 見本

> 先頭に `_` が付くファイルは出荷時の見本（不要になったら消してよい）。あなたの素材には `_` を付けない。

- `_example-rakuten-room.md` … この粒度・形式・参照元の書き方に揃える（実在の発信者の動画素材の実例。**中身のジャンルはあなたと違うので、数字・体験談を自分の台本に使わないこと**。不要になったら消してよい）
